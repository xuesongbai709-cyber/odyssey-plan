# 三种交付物骨架

按用户场景挑一种。默认是 HTML 报告（脚本直接出），下面三个骨架用于补文字、出海报、出 PPT。

## 一、Markdown 摘要（发给用户本人，能反复看）

```markdown
# {姓名} 的奥德赛计划 · {日期}

## 一句话
{三条路各自的重心一句话，不要结论}

## 现状
- 健康 {n} ｜ 工作 {n} ｜ 娱乐 {n} ｜ 爱 {n}
- 最意外的一项：{哪项，为什么}
- 重力清单（不解决，只当围墙）：1. … 2. …

## 判断标尺
> 工作观：{原话}
> 人生观：{原话}

## 三个版本

### A · {方案名}　{总分}　{结论}
- 论点：{一句话}
- 轨线：第 1 年 …／第 3 年 …／第 5 年 …
- 四维：资源 {n}｜喜爱 {n}｜自信 {n}｜一致 {n}
- 短板：{最疼的那句}
- 原型：{一周内做什么}

（B、C 同结构）

## 结论
推荐顺序：{X → Y → Z}
- {结构信号 1}
- {结构信号 2}

## 下周
1. {日期}　{动作}　找 {谁}　要拿到 {什么信息}
2. …
```

## 二、一页纸海报（打印或发朋友圈）

版面从上到下五块，总字数控制在 400 字内：

1. **标题**：`{姓名}的奥德赛计划 · 三个五年`
2. **三个竖条并排**（这是海报的视觉主体）：每条只有四行——方案名 / 一句话 / 总分 / 最疼的短板
   - 用颜色区分，A 冷、B 暖、C 绿，和 HTML 报告保持一致
3. **横轴时间条**：第 1 / 3 / 5 年三个刻度，只标每条路在第 5 年的落点
4. **围墙**：一到两行重力清单，字号最小，灰
5. **底部一句**：`先做这一件：{下周动作}`

设计要点：不要图表、不要数据表。雷达图只保留推荐那一条，小尺寸放角落即可。留白要比平时多一倍——这张纸的作用是让人愿意贴出来，不是让人读完。

## 三、PPT 大纲（8 页，团队工作坊或汇报用）

| 页 | 内容 | 要点 |
|---|---|---|
| 1 | 封面 | 姓名 / 日期 / 「三个五年，四条维度，一个先做」 |
| 2 | 为什么不是一条路 | 单路径的三个风险：信息最少时做最重决定、没有备份、失败等于人格否定 |
| 3 | 现状四仪表 | 四个数字 + 一句话说最意外的那项 |
| 4 | 判断标尺 | 工作观、人生观原文，字号要大——这是全场唯一的评价标准 |
| 5 | 三个版本对照 | 三列并排，只放论点 + 四维分数，不放细节 |
| 6 | 雷达图与短板 | 三张雷达叠一张图，指出结构性短板在哪一维 |
| 7 | 原型计划 | 每个方案一个原型，写清找谁、何时、要拿到什么信息 |
| 8 | 下一步 | 一句结论 + 一个日期。不要「综合考虑，稳步推进」 |

制作时交给 `workbuddy-pptx`，把这八页的标题与要点作为大纲传入。配色沿用报告的墨黑 + 三色方案：`#1d1e22` / `#4C6E8F` / `#A6542F` / `#4A7A5C`。

## 工作坊批量场景（10 人以上）

- 每人先独立填 `assets/odyssey-worksheet.md`（20 分钟，不讨论）
- 两两交换，只做一件事：指出对方 C 版里"伪装成 C 的 A"（10 分钟）
- 全场收四仪表，画一张分布图，找出集体短板（这往往是组织问题，不是个人问题）
- 每人只报一个原型，当场定日期
- 交付：不做个人报告，出一张集体海报 + 30 天后的复盘时间

批量场景下**不要让 AI 替每个人写方案**，只做规则校对（三版是否独立、C 版是否干净、原型是否合格）。
